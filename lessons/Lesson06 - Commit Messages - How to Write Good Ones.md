# Lesson 06: Commit Messages - How to Write Good Ones

## What this lesson covers

Why commit messages matter and how to write them well.

### Intuition to build
- A commit message is a letter to your future self (and teammates)
- Bad messages make `git log` useless; good ones make it a superpower
- Conventional Commits as an optional but widely-used standard

### What to include
- The 50/72 rule: subject line <= 50 chars, body wrapped at 72
- Imperative mood: "Add feature" not "Added feature"
- What to put in the body (why, not what)
- Examples: bad vs good commit messages side by side
- Brief intro to Conventional Commits: `feat:`, `fix:`, `docs:`, `chore:`
- When one-liners are fine vs when a body is needed
