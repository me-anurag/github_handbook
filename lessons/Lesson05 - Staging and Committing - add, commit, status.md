# Lesson 05: Staging and Committing - add, commit, status

## What this lesson covers

The core Git loop every developer runs hundreds of times a day.

### Intuition to build
- The three zones: working directory -> staging area -> repository
- Staging as a "draft pile" - you choose what goes into the next snapshot
- A commit is a permanent snapshot, not just a save

### What to include
- `git status` - reading the output
- `git add <file>` and `git add .`
- `git commit -m "message"`
- The full loop: edit -> add -> commit
- `git status` after a commit (clean working tree)
- Common mistake: committing without staging first

### Visual idea
A three-box diagram: Working Directory -> Staging Area -> Repository with arrows labeled `git add` and `git commit`
