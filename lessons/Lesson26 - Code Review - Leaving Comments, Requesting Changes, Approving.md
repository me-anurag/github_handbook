# Lesson 26: Code Review - Leaving Comments, Requesting Changes, Approving

## What this lesson covers

The other side of pull requests - how to review someone else's code well.

### Intuition to build
- Code review is a skill separate from coding - it's about communication as much as correctness
- A review isn't an attack; it's collaborative quality control
- "Request changes" is not the same as "this is bad code"

### What to include
- How to start a review on GitHub (Review changes button)
- Inline comments vs general comments
- Suggesting a specific change with GitHub's suggestion block
- The three outcomes: Comment, Approve, Request changes
- What to look for in a review (correctness, readability, edge cases, tests)
- Tone and language tips - how to give feedback that doesn't feel hostile
