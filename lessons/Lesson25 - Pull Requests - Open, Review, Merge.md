# Lesson 25: Pull Requests - Open, Review, Merge

## What this lesson covers

The primary collaboration mechanism on GitHub - proposing changes for review.

### Intuition to build
- A PR is a conversation around a set of commits, not just a merge button
- PRs are where code review, discussion, and CI checks all come together
- Merging a PR is a deliberate act of accepting responsibility for the change

### What to include
- Opening a PR on GitHub (base branch vs compare branch)
- Writing a good PR description (what, why, how to test)
- The PR page: Files changed, commits, checks, reviewers
- Merge options: merge commit vs squash merge vs rebase merge
- Closing a PR without merging
- Linking a PR to an issue with `Closes #42`
